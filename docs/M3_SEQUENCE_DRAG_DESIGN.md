# 시퀀스 메시지 높이 저장과 화면 연동

사용자 선택: 꺾임점 없이 메시지 화살표 전체를 생명선에 붙인 채 위아래로 이동한다.

## 저장 형식과 호환성

기존 경로 주석에 선택 숫자 필드 `offsetY`를 추가한다. `points`는 계속 내부 꺾임점만 담고, 수직 드래그로는 추가되지 않는다.

```text
%% @se-uml-route {"key":"[\"participant:User\",\"->>\",\"participant:Server\",0]","points":[],"offsetY":100}
```

- `offsetY`는 기존 65 단위 행 배치에 대한 수동 높이 차이다. 누락은 0이며 기존 파일은 같은 배치로 열린다. 0은 수동 높이 초기화다.
- 유한한 숫자만 허용한다. 손상된 주석을 읽으면 문서 교체 전에 실패하여 열린 문서를 유지한다.
- `readRoutes()`의 반환 타입과 `writeRoute()`의 기존 세 인수는 유지한다. `readSequenceOffsets()`·`writeSequenceOffset()`를 추가하고 꺾임점 편집에서도 기존 높이를 보존한다.
- 옛 앱도 주석을 읽을 수 있지만 새 높이는 적용하지 않는다. 옛 앱에서 해당 경로 주석을 다시 작성하면 높이 필드가 사라질 수 있다. 배치 주석 v1과 `types.ts`·`contracts.ts`는 변경하지 않는다.

## 계산과 호출자

`sequenceRowPositions()`는 앞 행과 최소 24 단위 간격을 유지한다. 메시지를 내리면 뒤의 메시지·활성화·블록 설명을 필요한 만큼 내려 원문 순서를 지킨다. 위로 이동할 때는 앞 행과 참여자 박스를 넘지 않게 한다.

`DiagramCanvas`는 화면 변환을 역산하여 수직 이동만 반영한다. 기존 꺾임점은 같은 높이 차이만큼 이동하고 메시지 양 끝의 x 좌표는 각 생명선에서 계산한다. 행 높이 계산을 설명 문구와 SVG 내보내기에도 공통 적용한다.

`onRouteChange`의 선택 세 번째 인수로 높이를 전달한다. 호출자는 `App.updateRoute`, UI 통합 테스트의 Harness다. `CanvasSvgRenderer`는 비활성 캔버스를 렌더링하므로 콜백을 실행하지 않는다. App은 경유점·높이를 합친 최종 원문을 `updateSource()`에 한 번 전달하여 한 Undo 단계로 기록한다. 기존과 같이 이 변경의 origin은 `code`다.

`DiagramStore`는 코드 편집 시 기존 메시지 키의 경유점과 높이를 함께 이어받는다. 파일 열기는 그 파일에 있는 높이를 사용한다. 같은 참여자·화살표가 반복되는 메시지의 경로 키는 기존 순번 방식이며 재정렬에 따른 대응은 이 변경의 범위 밖이다.

## 검증

수정 전 브라우저 회귀 검사는 y=300을 기대했지만 y=200에 남아 실패했다. 단위·통합은 형식 검증·원문 보존·행 순서·고정 연결·Undo/Redo·실패 원자성을 검사한다. 브라우저는 확대·화면 이동, 드래그·점 편집 구분, 취소, 참여자 순서 변경, 코드 편집·파일 복원을 검사한다. SVG 내보내기도 이동한 높이와 설명 위치를 검사한다.

설명은 가장 왼쪽 생명선보다 16 단위 왼쪽에 오른쪽 끝을 맞춘다. 글자 폭을 보수적으로 계산한 왼쪽 여백은 SVG 화면 변환으로만 적용하여 저장 좌표를 바꾸지 않는다. 화면 좌표 역변환·보기 초기화와 SVG 내보내기에 같은 여백을 적용한다.
