# M3 구현과 수동 검수

대상: `feat/m3-metadata-drag`. 기존 노드 배치 v1 및 `%% @se-uml-route` 주석을 유지한다.

## 구현한 기능

- 클래스·시퀀스 노드 이동, SVG 좌표 변환, 놓는 이벤트의 최종 좌표 반영.
- 드래그 중에는 미리보기만 변경하고 놓을 때 한 번 저장. Esc·포인터 취소·문서 변경은 취소.
- 노드 가장자리·중심 및 연결되지 않은 간선의 가까운 지점에 스냅. 기본 거리는 SVG 좌표 8이며 툴바에서 끌 수 있다. 이는 고객과 최종 합의할 기본 동작이다.
- 노드 오른쪽 아래 손잡이로 크기 조절. 최소 크기는 80×55 SVG 단위.
- `텍스트에 맞추기`로 실제 글자 너비와 전체 멤버 수에 맞게 크기 조절. 기존 3개 멤버 표시 제한 제거. 작은 박스에서는 텍스트를 자르고, 박스를 키우면 나머지 내용이 보인다.
- 클래스 관계와 시퀀스 메시지 선택·이동. 끝점은 노드/참여자에 유지하고 내부 경유점을 이동한다. 직선 이동 시 경유점 두 개를 만든다.
- 선 더블클릭 또는 `꺾임점 추가`, 원형 손잡이 이동, `꺾임점 삭제`/Delete, `경로 초기화`.
- 노드 크기·색상 편집도 수동 조정으로 보존하여 오래된 주석을 붙여 넣어도 유지한다.
- 배치 기록 전에 유효성을 검사하고, 경로 주석은 해당 키 한 줄만 갱신한다.

## 실행

```powershell
npm run dev
```

표시된 주소를 열고 **편집 캔버스**에서 검사한다. 공식 Mermaid 미리보기는 Mermaid 자체 배치를 사용하므로 수동 좌표·경로를 그대로 보여주지 않는다.

## 검수 순서

1. **노드 이동/Undo:** 클래스 예제에서 노드를 이동한다. 코드에 `@se-uml-layout`가 나타나고 위치가 바뀌어야 한다. Undo 한 번에 이전 위치로 돌아오고 Redo로 복구된다. 클릭만 하면 이력이 추가되지 않는다.
2. **취소:** 노드를 누른 채 이동한 뒤 Esc를 누르고 놓는다. 코드·좌표가 바뀌지 않아야 한다. 박스 크기와 간선 이동 중에도 확인한다.
3. **스냅:** 두 노드를 가까이 놓고 가장자리/중심을 살짝 어긋나게 이동한다. 가까워지면 정렬되어야 한다. 다른 노드를 연결되지 않은 선 근처로 옮기면 중심이 선에 붙는다. `노드·간선 스냅`을 끄면 자유롭게 이동한다. 자신에게 연결된 선에는 스냅하지 않는다.
4. **크기:** 노드를 클릭한 뒤 오른쪽 아래 파란 손잡이를 끈다. 위치는 그대로이고 크기만 바뀐다. 놓을 때 한 번 저장되며 Undo 한 번으로 복구된다.
5. **텍스트:** 아래 코드를 넣고 User를 선택해 `텍스트에 맞추기`를 누른다. 모든 멤버가 보이고 긴 글자가 잘리지 않아야 한다. 손잡이로 다시 크기를 바꿀 수도 있다.
6. **간선 이동/꺾기:** 노드 사이 선을 잡아 이동한다. 노드는 그대로이고 선의 중간 경로만 움직여야 한다. 선 더블클릭 또는 `꺾임점 추가`로 원을 만들고 끈다. 선택한 점을 삭제하고 경로 초기화·Undo도 확인한다.
7. **코드 편집:** 이동·크기·색상·간선을 수정한 뒤 기존 노드 이름을 유지하면서 새 클래스를 추가한다. 기존 편집값이 유지되어야 한다. 이름을 바꾸는 것은 삭제+추가이므로 위치 유지 대상이 아니다.
8. **저장/복원:** 파일 저장 후 시퀀스 예제로 전환하고 저장 파일을 연다. 노드 위치·크기·색상·꺾임점이 복원되어야 한다.
9. **시퀀스:** 아래 시퀀스 코드를 넣어 참여자 이동·크기 조절, 메시지 선 이동·꺾임점 편집을 확인한다. critical 제목을 바꿔도 기존 메시지 경로가 유지되어야 한다.
10. **오류:** 잘못된 문법을 입력하면 마지막 정상 그림이 유지되고 편집 도구가 비활성화되어야 한다. Undo로 정상 상태를 복구한다.

```text
classDiagram
  class User {
    +name: string
    +email: string
    +veryLongAttributeNameForResize: string
    +createdAt: string
    +login()
    +logout()
  }
  class Server
  class Database
  User --> Server : request
  Server --> Database : query
```

```text
sequenceDiagram
  participant User
  participant Server
  critical 주문 승인
    User->>Server: 요청
  option 시간 초과
    Server-->>User: 재시도
  option 승인 거절
    Server-->>User: 실패
  end
```

## 구조와 연결 범위

- `AlignmentSnap`은 기존 `ISnapStrategy`를 구현하고 App 생성 지점에 주입된다. 이동 중 미리보기와 Store 커밋에 같은 전략을 사용한다.
- 간선 기하는 `diagram-geometry.ts`, 주석 작성은 `route-editing.ts`에 둔다. 간선 수정은 기존 `updateSource()`를 통해 원문 변경 명령으로 반영되어 origin은 `code`다. GUI 전용 경로 명령을 공통 계약에 추가하려면 별도 계약 제안 PR로 진행한다.
- 시퀀스 경로도 기존 주석 형식에 참여자·화살표·동일 관계 내 순번 키를 사용한다. 동일한 양 끝·화살표의 메시지를 재정렬하거나 삽입하면 키가 달라질 수 있다. 의미상 영구 ID 보장은 후속 계약 사항이다.
- `types.ts`, `contracts.ts`의 공개 형식 및 노드 메타데이터 v1은 변경하지 않는다. 기존 M4·M5 파일의 연결 변경은 PR에서 해당 담당자의 검토를 받는다.
- 이미지 내보내기, 최종 UML 기호·글꼴, 모델 객체 생성 UI 확장은 이번 M3 작업 범위에 포함하지 않는다.

## 자동 검증

```powershell
npm run typecheck
npm test
npm run build
npm run test:browser
```

새 단위 테스트는 노드/간선 스냅, 잘못된 데이터 거부, 원문 보존, 시퀀스 경로 왕복, Undo, 드래그 전 크기·색상 변경 보존을 검사한다. `tests/m3-editing.spec.ts`는 실제 브라우저 조작을 검사한다.

## 이번 구현에서 확인한 결과

- 타입 검사 및 빌드 통과. Mermaid/ELK 번들의 기존 크기 경고는 남아 있다.
- 단위·통합 테스트 9개 파일, 44개 테스트 통과.
- 기존 회귀 테스트와 새 M3 테스트를 포함한 브라우저 테스트 12개 통과.
- PC에 Playwright 전용 Chromium이 없어서 설치된 Chrome과 임시 실행 설정으로 최종 빌드를 검증했다. 기본 브라우저 명령을 사용하려면 먼저 `npx playwright install chromium`을 실행한다.
- 기존 `package-lock.json`의 작업 상태는 변경하지 않았다.

## 자동 배치와 드래그의 경쟁 조건 보완

클래스의 기본 박스가 먼저 표시된 뒤 ELK 결과가 비동기로 도착한다. 기존에는 드래그 도중 결과가 도착하면 문서 변경 감지가 드래그를 취소하여 이동 메타데이터가 저장되지 않을 수 있었다.

- `LayoutInteraction`으로 포인터 조작 중 자동 배치 결과 반영을 미룬다. 계산 자체와 최초 표시는 막지 않는다.
- 놓을 때 수동 변경을 먼저 커밋하고 조작을 종료한다. 이전 자동 배치 결과는 Store의 기존 revision 검사로 폐기된다.
- 취소하면 대기하던 자동 배치를 허용하며 Undo 이력은 추가하지 않는다. 문서 변경·언마운트 시에도 대기를 해제한다.
- `layout-interaction.test.ts`는 수동 변경 우선, 취소, 문서 전환을 검사한다.
- `m3-layout-race.spec.ts`는 자동 배치 의존성의 완료 시점을 제어해 드래그 중 결과 도착을 재현한다. 대기 시간을 늘리거나 기존 드래그 검증을 제거하지 않는다.

추가 검증 결과: 타입 검사·빌드 통과, 단위·통합 47개 통과, Chromium 브라우저 13개 통과. 기존 실패 시나리오와 신규 경쟁 조건 재현 시나리오를 각각 10회씩 반복하여 총 20회 통과했다. 수정 전 빌드에서는 신규 재현 테스트가 실패하는 것을 확인했다.
